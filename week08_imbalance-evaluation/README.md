**왜 이 데이터?** 가입률 11.7%라 "전부 미가입"만 찍어도 정확도 88%가 나오는 적당한 불균형이고, "콜센터가 하루에 몇 통 걸 수 있나"라는 명확한 비용 구조가 있어서 임계값·향상도를 업무 언어로 옮기기 좋음. 7주차 모델을 그대로 이어받아 평가에만 집중.

**유의깊게 봤으면 하는 것**

- 모든 지표를 기준 모델과 비교
- PR-AUC의 기준선은 0.5가 아니라 양성 비율(0.117)
- 임계값은 test가 아니라 검증셋에서 정하기
- 샘플링·가중치가 예측 확률의 해석을 바꾼다는 점

## 필수 과제

- [ ] 전부 "미가입"으로 찍는 기준 모델의 정확도 계산
- [ ] 7주차 모델(`duration` 제외)의 혼동행렬, 정밀도, 재현율, F1, ROC-AUC, PR-AUC
- [ ] 임계값 0.5 / 0.3 / 0.2 / 0.1에서 정밀도·재현율 변화표
- [ ] 예측 확률 상위 10%, 20%, 30% 고객에게만 전화하면 전체 가입자의 몇 %를 잡는지 (향상도, 14.4.3)

## 심화 과제

- [ ] `class_weight="balanced"` / 언더샘플링 / 오버샘플링 비교 (샘플링은 train에만)
- [ ] 전화 한 통 비용과 가입 한 건 이익을 가정해 임계값별 수익 곡선 → 비용 비율을 바꾸면 최적 임계값이 어떻게 움직이는지

## 🔍 진행 가이드 & 유의할 점

### 도입 — Credit Card Fraud (10분)

1. 전부 "정상"으로 찍은 정확도 계산 → 약 99.8%
2. 같은 모델의 ROC-AUC와 PR-AUC를 나란히 → PR-AUC가 훨씬 낮음
3. PR-AUC의 기준선 = 양성 비율(약 0.0017)이라는 것 확인 → bank의 기준선은 0.117

### bank에서 유의해서 볼 것

- 기준 모델 정확도가 약 88.3% → "89%"는 아무것도 안 한 모델보다 1%p 남짓 나은 것
- PR-AUC는 0.5가 아니라 기준선 0.117과 비교해서 해석
- 임계값을 test에서 골라버리면 또 다른 누수 → 임계값은 검증셋(또는 CV)에서 정하고 test는 마지막에 한 번만
- 향상도는 "상위 20%에 전화하면 전체 가입자의 X%를 잡는다" 문장으로 정리 → 팀장 보고용 숫자
- 샘플링은 train 분할 후에만 (또는 `imblearn`의 Pipeline 안에서). 오버샘플링 후 CV하면 복제 행이 train·valid에 동시에 들어감
- `class_weight="balanced"`를 쓰면 예측 확률 자체가 부풀려짐 → 그 확률을 "가입 가능성 %"로 보고하면 안 됨
- 수익 곡선의 비용·이익 가정은 스터디원끼리 통일 (예: 통화 비용 : 가입 이익 = 1:5, 1:10 두 시나리오)

### AI 검증 포인트

정확도·F1만 보고하는지, 기준 모델 비교 없이 "좋은 성능"이라 하는지, 임계값 0.5를 고정으로 쓰는지
