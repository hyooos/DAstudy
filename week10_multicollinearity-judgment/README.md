## 🔍 진행 가이드 & 유의할 점

### 도입 — Many Analysts, One Data Set (15분)

1. 논문 결과부터: 29팀, 오즈비 0.89~2.93, 공변량 조합 21가지, 20팀만 유의
2. 데이터 구조 확인: 선수-심판 쌍(dyad) 단위, 피부색 평가자가 2명(`rater1`, `rater2`) → 두 평가를 평균낼지 하나만 쓸지부터가 "분석가의 선택"
3. 각자 통제변수 세트를 다르게 골라 로지스틱 회귀 → 오즈비 비교
4. "우리 `decisions.md`를 바꾸면 Home Credit TOP 3도 흔들릴까?"로 연결

### Home Credit에서 유의해서 볼 것

- `AMT_CREDIT`과 `AMT_GOODS_PRICE`는 상관 약 0.99 → 둘 다 넣으면 두 계수가 정보를 나눠 가져 부호가 뒤집힐 수 있음. "대출 금액 효과"는 무엇을 같이 넣었는지에 따라 달라짐
- 건물 정보 47열은 같은 항목의 AVG/MODE/MEDI 3종 → 세트 중 하나만 남기는 게 출발점
- `CNT_CHILDREN`–`CNT_FAM_MEMBERS`, `OBS_30`–`OBS_60`, `REGION_RATING_CLIENT`–`_W_CITY`도 공선성 후보
- 계수를 비교하려면 수치 변수는 표준화한 뒤 비교. 원-핫에서 `drop_first`를 안 하면 더미 변수 함정으로 VIF가 무한대
- `EXT_SOURCE_1/2/3`은 거의 모든 방법에서 상위지만 외부 신용점수라 심사팀이 바꿀 수 있는 요인이 아님 → TOP 3 보고 시 "바꿀 수 있는 요인 / 없는 요인" 구분
- "중요도 TOP 3"는 방법마다 다름 (표준화 계수, 순열 중요도, RF 중요도) → 순위 하나보다 "여러 방법에서 공통으로 상위인 변수"로 보고
- 신청 날짜가 없어 분할은 층화 무작위 분할만 가능 → 이것도 보고서 한계에 적기
- 한 페이지 보고서 순서: 결론 → 근거 숫자 2~3개 → 한계(승인된 대출만 있음, 날짜 없음, 관측 데이터라 인과 아님)
